# Version 0.8.0-rc.1 (2026-10-15)

- **Breaking**: `snouty runs events` always searches through the events-search API, the route that `snouty runs search` takes. Several `--match` terms work without an unstable feature, and every term must match. The output is a sample of the matching events in no fixed order, capped at `--limit`, and bootstrap events are left out. `--limit` accepts 1 to 999, down from 1000, and snouty checks it before any request. On a run that is not ready yet, the command waits until it is ready. The command needs tenant release 62.2 or newer, and `snouty doctor` warns on an older tenant. To read a whole timeline in order, use `snouty runs logs`; to count every match in a run, use `snouty runs search --count` ([#309](https://github.com/antithesishq/snouty/pull/309), [#319](https://github.com/antithesishq/snouty/pull/319), [#427](https://github.com/antithesishq/snouty/pull/427))
- **Breaking**: `snouty doctor --json` names some checks differently. A username and password are reported by the `credentials` check, as one warning with one next step, and the `basic_auth` check is gone. A username and password that hide a stored API key are one `credentials` warning, in place of the `credentials`, `basic_auth`, and `credential_sources` checks. The `runs-search` check is replaced by `events_search`, which no longer depends on an unstable feature, and warns instead of failing. Two more release checks, `execute_command` and `cancel_run`, warn when the tenant is too old for `runs exec` or `runs cancel`. An empty API key fails the `credentials` check. Doctor also asks the tenant whether CLI OAuth login is enabled, and the `oauth_configured` check warns when it is not; this request needs no credentials, and `--offline` skips it. Read the new names instead of `basic_auth` and `runs-search` ([#309](https://github.com/antithesishq/snouty/pull/309), [#324](https://github.com/antithesishq/snouty/pull/324), [#335](https://github.com/antithesishq/snouty/pull/335), [#341](https://github.com/antithesishq/snouty/pull/341), [#347](https://github.com/antithesishq/snouty/pull/347), [#355](https://github.com/antithesishq/snouty/pull/355), [#423](https://github.com/antithesishq/snouty/pull/423), [#429](https://github.com/antithesishq/snouty/pull/429), [#431](https://github.com/antithesishq/snouty/pull/431))
- **Breaking**: `snouty launch` with the `basic_test` or `basic_k8s_test` launcher needs a config image. Pass `--config`, `--config-image`, or `--param antithesis.config_image`; without one, the command fails before any API call ([#350](https://github.com/antithesishq/snouty/pull/350))
- **Breaking**: every compose service needs an explicit `image:`. Antithesis runs compose under its own project name, so the default tag that `docker compose build` gives a build-only service names no image there. `snouty launch` and `snouty validate` reject such a service before they push or start anything. Add an `image:` line to each service ([#394](https://github.com/antithesishq/snouty/pull/394))
- **Breaking**: `snouty launch --duration` must be at least 1 minute, so a typo such as `0` fails before it starts a run ([#403](https://github.com/antithesishq/snouty/pull/403))
- **Breaking**: `snouty launch` and `snouty debug` print the next steps after the `run_id` line, such as the `runs wait` or `runs exec` command for the new run. A script that reads the last line of their output gets a next step instead of the run ID. Add `--json` and read `.runId` instead ([#353](https://github.com/antithesishq/snouty/pull/353), [#407](https://github.com/antithesishq/snouty/pull/407))
- **Breaking**: `snouty debug --stdin` is removed. Pass the moment with `--input-hash`, `--vtime`, and one of `--run-id` or `--session-id`, which are now required flags, and pass any other parameter with `--param`. With `--run-id`, `snouty debug` also checks the run before it starts a billable session. It fails when the run does not exist, when the run is not yet ready (wait with `snouty runs wait <run_id> --until ready`), or when the run has no event under the input hash. The hash check uses the events-search count endpoint, so a run from a tenant release older than 62.2 fails it. Debugging with `--session-id`, or with a username and password, skips the checks ([#388](https://github.com/antithesishq/snouty/pull/388), [#401](https://github.com/antithesishq/snouty/pull/401), [#404](https://github.com/antithesishq/snouty/pull/404), [#406](https://github.com/antithesishq/snouty/pull/406), [#413](https://github.com/antithesishq/snouty/pull/413), [#426](https://github.com/antithesishq/snouty/pull/426))
- **Breaking**: `snouty runs logs --begin-input-hash` is removed. Use `--begin-vtime` alone to set the start ([#334](https://github.com/antithesishq/snouty/pull/334))
- **Breaking**: `snouty runs properties` no longer prints the property description: the `description` field is gone from `--json`, and `--detail` no longer shows it ([#327](https://github.com/antithesishq/snouty/pull/327))
- **Breaking**: `snouty login` sets up only single sign-on (OAuth) and API keys. It no longer offers to store a username and password, and when the tenant has no CLI OAuth, it asks for an API key straight away. To keep using a username and password with `launch` and `debug`, set `ANTITHESIS_USERNAME` and `ANTITHESIS_PASSWORD`. A username and password that an older snouty stored still work, and logging in again replaces them ([#325](https://github.com/antithesishq/snouty/pull/325))
- `snouty runs search` is stable and needs no unstable feature. Add `--count` to print how many events in the whole run match the query, with no limit, as `{"count": N}` under `--json`. On a run that is not ready yet, the command waits until it is ready. `--limit` accepts 1 to 999, checked before any request. The help explains that the output is a sample, and how the run's timelines relate the events. A long query rejection keeps its reason. The command needs tenant release 62.2 or newer ([#309](https://github.com/antithesishq/snouty/pull/309), [#420](https://github.com/antithesishq/snouty/pull/420), [#421](https://github.com/antithesishq/snouty/pull/421), [#427](https://github.com/antithesishq/snouty/pull/427))
- `snouty runs exec` is stable and needs no unstable feature. It works in any run that is in progress, a test run or a debugging session, and waits until the run is ready. Add `--container` to execute in a container instead of on the host, `--events` to print every event of the timeline while the script executes, and `--source-run-id` or `--source-session-id` to load a cold moment from another run. Rewarm progress prints on stderr, and passes through as `{"status":"rewarming",...}` records under `--json`. `--timeout` takes seconds or h/m/s units, and defaults to the server's timeout (10 minutes as of release 64.0) instead of 30 seconds. On a run that has stopped, the error names the `snouty debug` command for the same moment. The command needs tenant release 64.0 or newer ([#341](https://github.com/antithesishq/snouty/pull/341), [#351](https://github.com/antithesishq/snouty/pull/351), [#365](https://github.com/antithesishq/snouty/pull/365), [#368](https://github.com/antithesishq/snouty/pull/368), [#370](https://github.com/antithesishq/snouty/pull/370), [#383](https://github.com/antithesishq/snouty/pull/383), [#385](https://github.com/antithesishq/snouty/pull/385), [#408](https://github.com/antithesishq/snouty/pull/408), [#418](https://github.com/antithesishq/snouty/pull/418))
- `snouty launch` and `snouty debug` accept a launch response without a `statusCode` field. Tenant release 63.3 sends none, and with 0.7.2 every launch on such a tenant failed after the run had started ([#337](https://github.com/antithesishq/snouty/pull/337))
- `snouty launch` changes:
  - `--launcher` (`-l`) replaces `--webhook` and defaults to `basic_test`. `--webhook` and `-w` still work, are hidden from help, and print a deprecation warning. An unknown launcher fails with `unknown launcher: NAME` ([#349](https://github.com/antithesishq/snouty/pull/349), [#403](https://github.com/antithesishq/snouty/pull/403))
  - Add `--performance-tier` (`standard`, `fast`, or `turbo`) and `--filter-source-matching`, which suppresses the output of log sources that match an RE2 pattern and is checked before any API call ([#344](https://github.com/antithesishq/snouty/pull/344), [#361](https://github.com/antithesishq/snouty/pull/361))
  - Add `--allow-remote-images` to launch a compose config whose images are not all in the local image store. snouty warns about the images it cannot validate and pin, and about services with a `build:` stanza whose image is missing ([#394](https://github.com/antithesishq/snouty/pull/394))
  - When the config dir, or the current directory, is in a git checkout, the launch records the commit and branch as `vcs.*` params, and for a github.com `origin` the repository and a commit link. `--no-vcs` turns this off, and so does a pre-built config image. Every launch also sends `run.caller_type=snouty` ([#381](https://github.com/antithesishq/snouty/pull/381), [#407](https://github.com/antithesishq/snouty/pull/407))
  - The help documents user-defined `attrs.*` params ([#313](https://github.com/antithesishq/snouty/pull/313))
- Add `snouty runs cancel`: cancel a run that is starting or in progress. It needs tenant release 63.0 or newer ([#347](https://github.com/antithesishq/snouty/pull/347))
- `snouty runs wait` takes `--until ready|complete`. `ready` stops once the run is ready to use or already complete; `complete`, the default, waits for a terminal state as before. `runs wait` and `runs show` print a run's sub-status after its status, such as `in_progress:ready`, and `runs wait --json` adds `sub_status` ([#358](https://github.com/antithesishq/snouty/pull/358), [#418](https://github.com/antithesishq/snouty/pull/418))
- `snouty debug` takes `--title` to name the session and `--param` to pass extra parameters. A `--param` cannot replace the value of a dedicated flag ([#364](https://github.com/antithesishq/snouty/pull/364), [#412](https://github.com/antithesishq/snouty/pull/412))
- `snouty login` refuses an empty API key, and asks before a new credential replaces a different stored one. The closing summary says when it replaced a stored credential, and wraps at word boundaries on a terminal. Single sign-on serves branded sign-in pages, and its requests go through `ANTITHESIS_HTTPS_PROXY` and `ANTITHESIS_EXTRA_HEADERS` ([#356](https://github.com/antithesishq/snouty/pull/356), [#371](https://github.com/antithesishq/snouty/pull/371), [#375](https://github.com/antithesishq/snouty/pull/375), [#423](https://github.com/antithesishq/snouty/pull/423), [#429](https://github.com/antithesishq/snouty/pull/429))
- `snouty runs show` lists `attrs.*` params under Attributes and `vcs.*` params under Version Control, prints timestamps with their UTC offset, shows the event description when a run has no description, and points to `snouty runs properties` for a completed run ([#313](https://github.com/antithesishq/snouty/pull/313), [#320](https://github.com/antithesishq/snouty/pull/320), [#330](https://github.com/antithesishq/snouty/pull/330), [#342](https://github.com/antithesishq/snouty/pull/342), [#386](https://github.com/antithesishq/snouty/pull/386))
- `snouty runs list` has the columns RUN ID, STATUS, CREATED, LAUNCHER, and RUN. RUN is the test name, or for a run without one, the first line of its description or event description. `--detail` prints timestamps with their UTC offset ([#320](https://github.com/antithesishq/snouty/pull/320), [#359](https://github.com/antithesishq/snouty/pull/359), [#373](https://github.com/antithesishq/snouty/pull/373), [#386](https://github.com/antithesishq/snouty/pull/386))
- `snouty runs properties` shows the group apart from the name. `--detail` shows the property ID, says how many of the run's examples its table shows, and points to `runs logs`. A run with no property results prints `No properties found.` ([#323](https://github.com/antithesishq/snouty/pull/323), [#387](https://github.com/antithesishq/snouty/pull/387), [#409](https://github.com/antithesishq/snouty/pull/409), [#415](https://github.com/antithesishq/snouty/pull/415), [#418](https://github.com/antithesishq/snouty/pull/418), [#419](https://github.com/antithesishq/snouty/pull/419))
- `snouty runs logs` ends its human output with an `— end of logs` line on stderr. The event rendering shortens test-composer paths, commands, and container IDs, summarizes fault-injector settings and fuzzpipe records, and shows an injected command as `command injected`; `--detail` keeps every value whole ([#328](https://github.com/antithesishq/snouty/pull/328), [#354](https://github.com/antithesishq/snouty/pull/354), [#359](https://github.com/antithesishq/snouty/pull/359), [#367](https://github.com/antithesishq/snouty/pull/367), [#369](https://github.com/antithesishq/snouty/pull/369), [#410](https://github.com/antithesishq/snouty/pull/410))
- `snouty validate --timeout` takes seconds or h/m/s units, such as `5m`. A setup-complete timeout names the timeout and lists the likely causes. The compose divergence check keeps the variables that Antithesis sets, such as `HOME` and `USER`, so a compose file that interpolates one no longer reports a false divergence ([#314](https://github.com/antithesishq/snouty/pull/314), [#331](https://github.com/antithesishq/snouty/pull/331), [#370](https://github.com/antithesishq/snouty/pull/370))
- `--raw` on `runs logs`, `runs events`, and `runs search` is deprecated and hidden from help. It still works, and prints a warning on stderr. Use `--json` alone ([#362](https://github.com/antithesishq/snouty/pull/362))
- The `--verbose` request log no longer prints any part of a credential: an `Authorization` or cookie value shows as a stand-in, such as `Bearer [redacted]` ([#429](https://github.com/antithesishq/snouty/pull/429))
- `snouty docs --offline` also parses after a docs subcommand, as in `snouty docs search --offline` ([#357](https://github.com/antithesishq/snouty/pull/357), [#372](https://github.com/antithesishq/snouty/pull/372))
- The shell installer, now from cargo-dist 0.33, writes the env script that adds snouty to `PATH` to `~/.config/snouty/env.sh` (under `$XDG_CONFIG_HOME` when it is set) instead of `~/.local/bin/env`, and moves an existing one ([#338](https://github.com/antithesishq/snouty/pull/338))
- The cookbook has a recipe that copies private images into your Antithesis repository ([#316](https://github.com/antithesishq/snouty/pull/316))

# Version 0.7.1 (2026-09-01)

- `snouty validate` diagnoses a compose render that is not JSON: the error names the compose CLI that ran and quotes the line the parser stopped on. `--allow-compose-divergence` now covers this failure, so a compose CLI that ignores `--format json` no longer blocks the check ([#294](https://github.com/antithesishq/snouty/issues/294))
- `snouty doctor` reports more than one credential source. snouty uses the first source it finds, so an exported `ANTITHESIS_USERNAME` and `ANTITHESIS_PASSWORD` hide the API key that `snouty login` stored. doctor now warns, names the credential it uses and the credentials it ignores, and states the action that hands the run to the next source ([#292](https://github.com/antithesishq/snouty/issues/292))
- snouty now supports proxied repository urls ([#291](https://github.com/antithesishq/snouty/pull/291))

# Version 0.7.0 (2026-08-26)

The largest changes come first. A breaking change is marked.

- Add `snouty login`: sign in at the terminal with browser-based OAuth or with an API key, keep more than one profile, and store credentials in the macOS keychain or in a credentials file on Linux. A GitHub Actions workflow authenticates with OIDC and needs no stored secret. Username and password authentication is deprecated: `snouty launch` and `snouty debug` still accept it, and print a warning that points to `snouty login` ([#157](https://github.com/antithesishq/snouty/pull/157), [#173](https://github.com/antithesishq/snouty/pull/173), [#178](https://github.com/antithesishq/snouty/pull/178), [#212](https://github.com/antithesishq/snouty/pull/212))
- **Breaking**: `snouty runs logs`, `snouty runs events`, `snouty runs search`, and `snouty runs build-logs` share one output format. A `moment HASH VTIME` divider opens each timeline segment, and each event below it prints on one line in the form that suits its kind: SDK assertion, fault, container lifecycle, or test composer. Add `-d/--detail` for full-width vtimes, source locations, event details, and the test composer's captured output. Add `--json` for one JSON object per line. Each line prints as it arrives, so a pipe or a file receives output while the run continues. ([#206](https://github.com/antithesishq/snouty/pull/206), [#222](https://github.com/antithesishq/snouty/pull/222), [#285](https://github.com/antithesishq/snouty/pull/285))
- `snouty validate` streams container logs in real time and in order, treats `--timeout` as one budget for the whole run (default 120 seconds), refuses to start when the project still holds containers from an earlier run, reports a compose failure as itself instead of as an environment divergence, fails when the compose file resolves differently in the Antithesis environment, and detects a setup-complete event that the SDK writes early ([#168](https://github.com/antithesishq/snouty/pull/168), [#214](https://github.com/antithesishq/snouty/pull/214), [#218](https://github.com/antithesishq/snouty/pull/218))
- snouty works with the `docker compose` plugin as well as the standalone `docker-compose` binary. It announces the container engine it detected during `launch` and `validate`, and points to the other engine when that one holds a missing image. Docker Compose v2.24.7 or newer is now required, and snouty checks the version before it starts ([#170](https://github.com/antithesishq/snouty/pull/170), [#171](https://github.com/antithesishq/snouty/pull/171), [#172](https://github.com/antithesishq/snouty/pull/172), [#175](https://github.com/antithesishq/snouty/pull/175), [#214](https://github.com/antithesishq/snouty/pull/214))
- Add `snouty runs wait`: poll a run until it reaches a terminal state — completed, cancelled, or incomplete ([#221](https://github.com/antithesishq/snouty/pull/221))
- Add two commands behind unstable feature flags. `snouty runs search` queries a run's events with the event-set DSL (`SNOUTY_UNSTABLE_FEATURES=runs-search`). `snouty runs exec` runs a bash script in a run's live session at a given moment, on a fresh branch of the multiverse (`SNOUTY_UNSTABLE_FEATURES=runs-exec`); its API is unstable and most tenants do not offer it ([#206](https://github.com/antithesishq/snouty/pull/206), [#208](https://github.com/antithesishq/snouty/pull/208))
- `snouty runs events` matches server-side and takes `--limit` to cap the number of events it prints (default 50). More than one `--match` term needs the events-search API, behind the `runs-search` unstable feature ([#176](https://github.com/antithesishq/snouty/pull/176), [#206](https://github.com/antithesishq/snouty/pull/206))
- `snouty launch` accepts an unknown `antithesis.*` param, so a new platform param works without a snouty update. Add `--param antithesis.images` to register an image the config parser cannot discover. `antithesis.filter_logs_matching` is checked before any API call, so a bad pattern fails at once ([#161](https://github.com/antithesishq/snouty/pull/161), [#213](https://github.com/antithesishq/snouty/pull/213), [#276](https://github.com/antithesishq/snouty/pull/276))
- **Breaking**: `snouty doctor --json` writes `settings` as an object keyed by setting name, and writes an unset setting as `null`. A caller reads one value with `jq .settings.tenant` ([#285](https://github.com/antithesishq/snouty/pull/285), [#288](https://github.com/antithesishq/snouty/pull/288))
- **Breaking**: `snouty debug --stdin` accepts JSON only. The `Moment.from({...})` input format is removed ([#243](https://github.com/antithesishq/snouty/pull/243))
- The VTIME argument on `snouty runs logs` is optional. Omit it to stream to the branch's current end ([#264](https://github.com/antithesishq/snouty/issues/264))
- A GET request that fails with a transient network error — a connect error, a reset, or a DNS failure — is retried up to 3 times, with backoff between the attempts ([#249](https://github.com/antithesishq/snouty/issues/249))
- snouty caches an API response only when the server's cache headers permit it. Set `api_cache_respect_headers = false` to cache without that requirement ([#263](https://github.com/antithesishq/snouty/issues/263), [#272](https://github.com/antithesishq/snouty/issues/272))
- Add the `ANTITHESIS_HTTPS_PROXY` setting to proxy snouty's API requests without affecting docker or podman, and `ANTITHESIS_EXTRA_HEADERS` to put additional headers on those requests ([#158](https://github.com/antithesishq/snouty/pull/158), [#164](https://github.com/antithesishq/snouty/pull/164))
- Add an update channel. `stable` is the default and installs the latest release; `unstable` also considers pre-releases. Set it with `update_channel` or `SNOUTY_UPDATE_CHANNEL`, or override it for one run with `snouty update --channel unstable` ([#195](https://github.com/antithesishq/snouty/pull/195))
- `snouty docs search` treats the query as literal text. Add `--match` to use FTS5 query syntax ([#166](https://github.com/antithesishq/snouty/pull/166))
- `snouty runs list --limit 0` is rejected ([#285](https://github.com/antithesishq/snouty/pull/285))
