Give Docker or Podman the credential for the tenant's container registry

A Docker credential helper for the tenant registry, registry.<tenant>.antithesis.com. Docker and Podman run the docker-credential-snouty binary, which is installed next to snouty. To use it, add the registry to "credHelpers" in ~/.docker/config.json for Docker, or in ~/.config/containers/auth.json for Podman:

  {
    "credHelpers": {
      "registry.<tenant>.antithesis.com": "snouty"
    }
  }

Then `docker push`, `docker pull`, `podman push` and `podman pull` sign in with your snouty credential, and `docker login` or `podman login` is not necessary. Podman also reads ${XDG_RUNTIME_DIR}/containers/auth.json and ~/.docker/config.json. On macOS, put the entry in the file on your Mac, not in the podman machine.

get reads a server URL from stdin, and prints the credential for it as JSON. Snouty owns the credential, so the other actions do not change it. store fails, so `docker login` and a `podman login` with a username fail, and tell you to run `snouty login` or to set ANTITHESIS_API_KEY. A `podman login` with no username succeeds, because get gives it the credential. erase reads stdin, changes nothing, and succeeds, so `docker logout` and `podman logout` do not fail; the engine continues to get the credential from snouty. list fails, because Docker and Podman do not call it for a "credHelpers" entry.

The username is snouty-token. The password is your API key, or your OAuth access token from `snouty login`. Each get refreshes the OAuth token, so a long push has the full lifetime of the token. When the refresh fails, get uses the stored token until it expires, and writes a warning to stderr.

The engine does not give the helper a profile, so get uses the profile whose settings agree with the requested host: its repository is on that host, and the host is registry.<tenant>.antithesis.com for its tenant. The selected profile (--profile or ANTITHESIS_PROFILE) wins when it agrees. Then the top-level defaults win. Then one named profile can agree; when more than one does, get fails, and you set ANTITHESIS_PROFILE to select one. A profile whose settings are not valid, such as an invalid tenant, is skipped, also when it is the selected profile. Environment variables, such as ANTITHESIS_TENANT, ANTITHESIS_REPOSITORY and ANTITHESIS_API_KEY, apply to every profile. The engine starts the helper in any working directory, such as a cloned repository, so the helper does not read a ./.snouty.toml. It reads the global settings file, and a settings file that --settings or SNOUTY_SETTINGS_PATH names.

When no profile agrees with the host, get prints "credentials not found in native keychain" and exits with status 1, as Docker and Podman expect. Each other error goes to stdout as one line, where the engine shows it, and to stderr in full.

The docker-credential-snouty binary runs the same helper code as this command, and does not run snouty. Use this command to debug the helper: it also takes {{ t("--profile")? }} and {{ t("--settings")? }}, which the engine does not give.

Examples:
  echo registry.acme.antithesis.com | snouty docker-credential get
