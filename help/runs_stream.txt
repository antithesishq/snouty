Stream a run's property events as they happen, until the run is final.

Each event prints as one line:

  catalogued <property id> <name>             a new property appears
  failed <property id> <input hash> <vtime>   a counterexample of the property
  passed <property id> <input hash> <vtime>   an example of the property
  failed|passed <property id>                 the property failed or passed, with no new sample
  completed <run id>                          the run is final, and the stream ends

A non-event property has no moments, so its failed and passed lines show the sample value as JSON. A sample prints only the first time the server sends it. Look up a property with `snouty runs property <run_id> <property_id>`, and read the logs at a moment with `snouty runs logs <run_id> <input hash> <vtime>`.

The stream does not show the current results. It shows only events, and it is silent until one happens. To get the current results and then follow them, start the stream first, then read `snouty runs properties <run_id>`. If you start the stream first, you do not miss an event. A stream for a run that is already final prints `completed` and ends immediately. The stream of a new run opens a few minutes after the run starts, and snouty waits until it does.

If the stream ends before the run is final, snouty exits with an error. Start the stream again, then read the current results.

Streaming needs a run created on release 65.3 or later.

Examples:
  snouty runs stream <run_id>
  snouty runs stream <run_id> --property <property_id>

Add --json for machine-readable output. Each event prints as one JSON object, with an `event` key and the fields above. Each vtime is a JSON number:
  snouty --json runs stream <run_id> | jq -r 'select(.event == "failed") | .property_id'
