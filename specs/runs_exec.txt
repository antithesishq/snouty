# snouty runs exec
#
# Execute a bash script in the live session of a test run, at a specific
# moment in the run's execution timeline.
#
# Session semantics verified against the live API (orbitinghail, release
# 60.0): the command needs a live session, and a run keeps one while it runs
# and for a while after it completes. A run whose session has ended answers
# 400. The window is not documented; a run that completed 48 minutes earlier
# still executed, and runs that completed 17 hours and 1 day earlier did not.
# The mock below models the simpler rule "in-progress only", which is enough
# to drive both paths. The script executes on a fresh branch of the multiverse
# — the response moments carry a new input_hash — so the running test is not
# disturbed.
#
# The stream shape follows the release 64.0 spec (`POST
# /runs/{run_id}/command`), verified against the live API (orbitinghail,
# release 64.0): zero or more command-output events in the same `Event` shape
# `runs logs` receives (`moment`, `output_text`, `source.stream`, with `info`
# for stdout and `error` for stderr), then exactly one result whose `status`
# is `exited` or `timed_out`, unless the stream ends with a `Stream_Error`
# line.
#
# When the server rewarms a cold moment, the stream begins with progress
# records, `{"status":"rewarming","percent_complete":N}`: the first is at 0,
# the last is at 100, and all come before the command's output. Verified
# against the live API (orbitinghail, release 64.0, 2026-10-07): one rewarm
# sent 35 records over 22 seconds.
#
# Release 64.0 requires `container` in the request: a container name or ID,
# or `_ANTITHESIS_HOST` for the host. Earlier releases reject the field, so
# `runs exec` needs release 64.0 or newer, and `snouty doctor` warns on an
# older tenant.
#
# snouty's contract:
#
#   - The script executes on the host, or in the container that --container
#     names.
#   - Without --events, the stream holds only the script's output, and
#     snouty prints it as plain stdout and stderr. --events asks the server
#     for every event of the timeline while the script executes
#     (`include_system_logs`), and snouty prints them as `runs logs` does,
#     the script's output included. Verified against release 64.0
#     (orbitinghail): the timeline carries assertions, test-composer tasks,
#     fault-injector and journald events, and metadata about the command
#     itself, most of which have no output text.
#   - The script comes from the SCRIPT argument, or from stdin when SCRIPT is
#     omitted. Omitting it is the only way to read stdin; a pipe, a redirect,
#     and a heredoc all work, and a script over 2 MiB is refused.
#   - Without --events, an event's `output_text` is routed by
#     `source.stream`: `error` to snouty's stderr, and anything else, a
#     missing stream included, to snouty's stdout. An event without
#     `output_text` goes to stderr as raw JSON. stdout carries only output
#     text, so `snouty runs exec ... | jq` composes.
#   - Rewarm progress goes to stderr: when stderr is a terminal, a progress
#     bar that gives way to a `rewarming moment: done` line, and otherwise one
#     `rewarming moment: N%` line per record. A rewarm that ends early keeps
#     its last percentage in view (tests/exec_pty.rs covers the terminal).
#     stdout keeps only the script's output, with or without --events.
#   - On `exited`, a trailer on stderr documents the branch's end moment, to
#     chain a follow-up command from.
#   - `exited` with code 0 is success. Any other terminal state fails snouty
#     with exit code 1: a non-zero code (reported, not forwarded), a
#     `timed_out` result, or a stream that ends with no result at all — exit
#     0 must mean "the script ran and exited 0".
#   - `--json` passes the NDJSON through, progress records included, with
#     vtimes normalized to exact JSON numbers (like `runs logs --json`) and no
#     trailer or progress display; exit semantics are unchanged.
#   - The API is still changing, so snouty is lenient about events: no event
#     shape fails snouty. Only the last line is read as the result.
#
# Every successful invocation executes a script inside a live session, so
# everything below the credential-free check is gated behind `[staging] skip`,
# like `snouty debug`: staging has no reliably-live run to execute against.

# The command is in `runs --help`.
snouty runs --help
stdout 'exec.*Execute a command in a run'
snouty runs exec --help
! stdout 'SNOUTY_UNSTABLE_FEATURES'

stderr 'No Antithesis credentials found.*'
! stderr 'unstable feature'

# Happy path: output events are routed by stream — `info` lines to stdout,
# `error` lines to stderr — and the end-moment trailer lands on stderr.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 'uname -a'
stdout 'Linux antithesis 6.12.0'
! stdout 'virtual clock drift'
stderr 'warning: virtual clock drift detected'
stderr 'end moment: -8206006569229276678 398.492'
! stderr '"status"'

# Omitting SCRIPT reads the script from stdin. That is the only way to do it:
# there is no `-` spelling, so there is one way to trigger a stdin read.
stdin exec_script.txt
snouty runs exec run-2 -3625518438076122494 398.4898056755774
stdout 'Linux antithesis 6.12.0'

# A literal `-` is therefore just a script, not a stdin marker. The mock's
# default branch runs it like any other script.
#
# Deliberately no `stdin` line here, unlike the block above. `-` is a script, so
# snouty never reads stdin, and feeding it some anyway races snouty's exit: the
# harness's write gets EPIPE when snouty exits first, which it does often enough
# on macOS to fail this spec. Nothing is lost — the mock answers every script
# with the same default output, so stdin's presence proves nothing here.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 -
stdout 'Linux antithesis 6.12.0'

# An empty stdin is "no script", caught before any API call. (The
# nothing-on-stdin-at-a-terminal case can't be driven here: the harness always
# provides a non-interactive stdin.)
stdin empty_script.txt
! snouty runs exec run-2 -3625518438076122494 398.4898056755774
stderr 'no script provided.*'

# A script with no output prints nothing but the trailer: exec's stdout is
# the script's stdout, not a report.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 'true'
! stdout '.'
stderr 'end moment: -8206006569229276678 398.492'

# A non-zero exit code fails snouty (with exit code 1 — the script's code is
# reported, not forwarded). The trailer still shows: the branch reached its
# end moment, exit code notwithstanding.
! snouty runs exec run-2 -3625518438076122494 398.4898056755774 'exit 5'
stderr 'command exited with code 5'
stderr 'end moment: -8206006569229276678 398.492'

# `exit_code` is nullable: a command the session killed reports no code. That
# is not a success, so snouty fails and says so rather than claiming exit 0.
! snouty runs exec run-2 -3625518438076122494 398.4898056755774 no-exit-code
stderr 'command exited without reporting an exit code'

# A script that outlives the timeout ends with a `timed_out` result, which
# snouty reports as a failure. Output produced before the timeout is still
# shown. The result carries no end moment — its `last_moment` is informational,
# the command may still be running — so there is no trailer.
! snouty runs exec run-2 -3625518438076122494 398.4898056755774 'sleep 60' --timeout 30
stdout 'still working'
stderr 'command timed out after 30s'
! stderr 'end moment'
! stderr 'rewarm'

# Without --timeout, the server's default applies (600 seconds as of release
# 64.0), and snouty names --timeout.
! snouty runs exec run-2 -3625518438076122494 398.4898056755774 'sleep 60'
stderr 'command timed out after the server.s default timeout'
stderr 'set a longer timeout with --timeout'

# --timeout is forwarded to the server as timeout_seconds (the mock echoes
# back the value it received). Without it, the request leaves out
# timeout_seconds, so the server's default applies.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request --timeout 45
stdout 'timeout_seconds=45'

snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request
stdout 'timeout_seconds=absent'

# Without --container, the script executes on the host.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request

# --container names the container to execute in, by name or ID.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request --container my-service

# Without --events, the request leaves out include_system_logs, so the server

snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request

stdout '\[bash_command\] .*include_system_logs=true'

# --events prints every event of the timeline as `runs logs` does, all on
# stdout: a `moment HASH` divider, then `VTIME [source] payload` lines. The
# trailer still goes to stderr.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 with-system-logs --events
stdout 'moment -8206006569229276678'
stdout '398.49.* \[bash_command\] fuzzpipe Command received$'
stdout '398.49.* \[bash_command\] script says hi'
stdout '398.49.* \[workload\] workload says hi'
stderr 'end moment: -8206006569229276678 398.492'

# With --events and --json, every event passes through as NDJSON, then the

snouty --json runs exec run-2 -3625518438076122494 398.4898056755774 with-system-logs --events
stdout '"fuzzpipe":\{"event_type":"Command received"\}'

stdout '"status":"exited"'

# --source-run-id and --source-session-id name the run, or that run's session, that a cold
# moment comes from (source_run_id and source_session_id). The server rewarms
# the moment by replaying that run's inputs. Verified against release 64.0
# (orbitinghail): without either, a moment off the session's own timeline
# answers 400 "Moment not warm", and the rewarm counts against --timeout.
# Without the flags, neither field is sent.
snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request
stdout 'source_run_id=absent source_session_id=absent'

snouty runs exec run-2 -3625518438076122494 398.4898056755774 print-request --source-run-id 1f1211ea49946d4f63a92d65ee42476d-64-0

# VTIME is parsed by clap into the typed vtime the request body carries, so a
# non-numeric value is rejected before any API call.
! snouty runs exec run-2 -3625518438076122494 not-a-number 'uname -a'
stderr 'invalid value .*not-a-number.*'
stderr 'vtime is not a finite decimal number'

# --timeout must be at least 1: a 0-second timeout can only ever time out.

! snouty runs exec run-2 -3625518438076122494 398.4898056755774 'uname -a' --timeout 0
