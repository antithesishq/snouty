Launch a debugging session

Identify the target run with {{ t("--run-id")? }}. Use {{ t("--session-id")? }} in its place only for a moment that names a session ID rather than a run ID.

Example:
  {% filter cmd %}
  snouty debug \
    --run-id 9043254f65c9c65d63fe043a0abfc7fc-53-1 \
    --input-hash 6057726200491963783 \
    --vtime 329.8037810830865 \
    --title "stalled leader election" \
    --description "debug this moment" \
    --recipients "team@example.com" \
    --duration 2h
  {% endfilter %}

The session stays available for the time that {{ t("--duration")? }} gives, from 30 minutes to 6 hours. Without it, the server sets the time. Runs from releases before 67 ignore it.{% if !cli %} {{ duration_format() }}.{% endif %}

Extra parameters can be passed with {{ t("--param")? }}{% if cli %}, as for `snouty launch`{% endif %}. A {{ t("--param")? }} cannot replace the value of a dedicated {% if cli %}flag{% else %}param{% endif %}, such as {{ t("--title")? }}:
  {% filter cmd %}
  snouty debug --run-id <run_id> --input-hash <hash> --vtime <vtime> \
    --param attrs.team=payments
  {% endfilter %}

The new session's run ID is the `run_id` value in the output, or `runId` with {{ t("--json")? }}. The session starts at the moment that it debugs. Wait until it is ready, then run commands at that moment:
  {{ t("snouty runs wait <session_run_id> --until ready")? }}
  {{ t("snouty runs exec <session_run_id> <hash> <vtime> 'ps aux'")? }}

{% if cli %}
Add --json for machine-readable output. The response prints as one JSON object:
  {% filter cmd %}
  snouty debug --json --run-id <run_id> --input-hash <hash> --vtime <vtime> |
    jq -r .runId
  {% endfilter %}
{% else %}
With {{ t("--json")? }}, the response prints as one JSON object.
{% endif %}
