# Version 0.10.0 (2026-11-11)

- **Breaking**: `snouty runs usage` selects runs by a time window and has no row limit; `-n`/`--limit` is gone. With no filter it shows the runs that ended in the last week (4 weeks with `--rollup week`, 6 months with `--rollup month`), oldest first, instead of the 10 newest runs, newest first. Use `--after` and `--before` to choose the window. The JSON keys do not change ([#688](https://github.com/antithesishq/snouty/pull/688))
- **Breaking**: `snouty runs search` fails when the stream sends an error line, as the other streaming commands do, instead of printing it as a row. A query that maps events to an object with an `error` key now fails; use another key name ([#680](https://github.com/antithesishq/snouty/pull/680))
- **Breaking**: `snouty validate` removes the compose project's named volumes when it brings the project down, and fails when a volume that the compose file declares already exists. Validation on 0.9.x left those volumes behind, so the first 0.10.0 run on such a config fails; run `docker compose -f <file> down --volumes` (or `podman compose`) once to remove them ([#683](https://github.com/antithesishq/snouty/pull/683))
- `snouty mcp` and the `launch --max-compute-hours`, `launch --setup-timeout` and `debug --duration` flags are stable and no longer need `SNOUTY_UNSTABLE_FEATURES`. The `mcp` and `teams` ids have no effect, so a config that sets them keeps working. `launch --duration` is deprecated and prints a warning; use `--max-compute-hours` ([#704](https://github.com/antithesishq/snouty/pull/704), [#710](https://github.com/antithesishq/snouty/pull/710))
- `snouty runs usage <run_id>...` shows the compute hours of the named runs, in the order given ([#688](https://github.com/antithesishq/snouty/pull/688))
- `snouty runs usage --after` and `--before`, and `snouty runs list --created-after` and `--created-before`, take a relative time, such as `now`, `5 hours ago` or `2 weeks ago` ([#688](https://github.com/antithesishq/snouty/pull/688))
- When an AI agent runs `snouty launch`, the run records the agent, its version and its session ID as the `attrs.agent`, `attrs.agent_version` and `attrs.agent_session_id` attrs. A `--param` replaces a recorded value ([#705](https://github.com/antithesishq/snouty/pull/705), [#713](https://github.com/antithesishq/snouty/pull/713))
- Add `snouty runs exec --include-filtered-logs`, with `--events`: this feature includes logs that the run's log filters would normally drop ([#698](https://github.com/antithesishq/snouty/pull/698))
- snouty verifies TLS certificates signed with an ECDSA P-521 key, such as the root CA of some TLS-inspecting corporate proxies ([#691](https://github.com/antithesishq/snouty/pull/691))
- `snouty login` checks for single sign-on and signs in at the `base_url` setting, instead of ignoring a `base_url` in a settings file ([#697](https://github.com/antithesishq/snouty/pull/697))
- `snouty doctor` reports the credential problem that it found: a stored OAuth token that cannot be renewed, a GitHub Actions OIDC token that cannot be fetched, or a blank `ANTITHESIS_API_KEY`, with the step that fixes it, instead of reporting the API as unreachable. It warns that the environment hides a stored credential only when one is hidden, and warns that CLI OAuth login is disabled only when no credential works ([#682](https://github.com/antithesishq/snouty/pull/682), [#693](https://github.com/antithesishq/snouty/pull/693), [#699](https://github.com/antithesishq/snouty/pull/699), [#700](https://github.com/antithesishq/snouty/pull/700), [#702](https://github.com/antithesishq/snouty/pull/702), [#703](https://github.com/antithesishq/snouty/pull/703), [#706](https://github.com/antithesishq/snouty/pull/706), [#711](https://github.com/antithesishq/snouty/pull/711))
- When the tenant rejects a credential, commands suggest `snouty doctor` and `snouty login`. When no credential is found in a GitHub Actions job, snouty suggests adding `id-token: write` to the job's `permissions` instead of `snouty login` ([#695](https://github.com/antithesishq/snouty/pull/695), [#702](https://github.com/antithesishq/snouty/pull/702), [#703](https://github.com/antithesishq/snouty/pull/703))
- `snouty settings show` lists the credentials file after the settings files. The text heading for the files is `files:` ([#712](https://github.com/antithesishq/snouty/pull/712))
- Whitespace around `ANTITHESIS_API_KEY` is ignored, and a key of only whitespace is an error that names the variable ([#699](https://github.com/antithesishq/snouty/pull/699))
- `snouty settings show` lists the credentials file after the settings files. With `--json`, the `files` array holds an entry with `"type": "credentials"`. With no files, the text line reads `files: none` instead of `settings files: none` ([#712](https://github.com/antithesishq/snouty/pull/712))
- `snouty launch` prints `snouty runs show --web <run_id>` as a next step ([#690](https://github.com/antithesishq/snouty/pull/690))
- `snouty validate` removes the compose project's named volumes when it brings the project down, so the next validation starts on fresh volumes ([#683](https://github.com/antithesishq/snouty/pull/683))
- The README shows how to install snouty with Nix ([#684](https://github.com/antithesishq/snouty/pull/684))

A `moment HASH VTIME` divider opens each timeline segment, and each event below it prints on one line in the form that suits its kind: SDK assertion, fault, container lifecycle, or test composer. Add `-d/--detail` for full-width vtimes, source locations, event details, and the test composer's captured output. Add `--json` for one JSON object per line. Each line prints as it arrives, so a pipe or a file receives output while the run continues.
