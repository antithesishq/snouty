# snouty runs
#
# List all Antithesis runs.
#
# Assertions prefixed with [!staging] are skipped when SNOUTY_STAGING is
# set: they assert against hardcoded mock data (or behaviors that only make
# sense against the in-process mock) that does not exist on the live staging
# backend. Unprefixed assertions are structural and run in both modes.
#
# Run-id scoped read responses may be cached under
# $XDG_RUNTIME_DIR/snouty/api-cache-v3 (under the user temp dir on macOS).
# Caching is internal and must not change command output or required arguments.
# GET requests that fail at the transport level (connect errors, resets, DNS
# failures) are retried up to 3 times with backoff; a served HTTP response of
# any status is never retried, and mutations (the launch, debug, and exec
# webhooks) are sent exactly once (#249).

# The command authenticates with the Antithesis API using
#    ANTITHESIS_API_KEY and ANTITHESIS_TENANT env vars. Every endpoint other
#    than launch requires an API key, so unlike the launch commands,
#    username/password authentication is not supported.
! snouty runs
stderr 'No Antithesis credentials found.*'

# message instead of sending a request the API would reject with a 403.

env ANTITHESIS_TENANT=testtenant
! snouty runs

# `snouty runs logs` renders classified event blocks: a `moment HASH VTIME`
# divider (full precision, pasteable back into `runs logs`) opens each
# timeline segment, and each event under it renders as one
# `VTIME [source] payload` line. Antithesis shapes get their own concise
# forms: an SDK assertion shows a verdict badge (HIT/FAIL on evaluations,
# CATALOG on the hit:false registrations the SDK emits at startup) with its
# label and message; a fault shows its type, disruption and nodes;
# test-composer records show their task lifecycle or key=value chatter.
# Without VTIME the stream runs to the branch's current end.
mock-runs-server
snouty runs logs run-1 -123
stdout '^moment -123 1\.0$'

stdout '^moment -456 2\.0$'
