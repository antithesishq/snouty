Launch a test run

Example:
  snouty launch --launcher basic_test --config ./config \
    --test-name "my-test" \
    --description "nightly test run" \
{%- if teams() %}
    --max-compute-hours 24 \
{%- else %}
    --duration 30m \
{%- endif %}
    --recipients "team@example.com"

The -c/--config flag points at a local directory containing docker-compose.yaml (this is the config image source, unrelated to snouty's own settings file). snouty does not build or pull your service images, and it ignores `build:` stanzas, so build them first, for example with `docker compose build`. By default, every image that the run needs must be in the local image store, and snouty pushes them automatically. Add {{ t("--allow-remote-images")? }} to skip this check for images that are not on this machine.

Alternatively, pass a pre-built config image directly:
  snouty launch --launcher basic_test \
    --config-image us-central1-docker.pkg.dev/proj/repo/config:latest \
{%- if teams() %}
    --max-compute-hours 24
{%- else %}
    --duration 30m
{%- endif %}

{% if teams() %}
{{ t("--max-compute-hours")? }} sets the run's budget of compute hours, up to 1000. One compute hour is one core running for one hour. The server default is 48 compute hours. Requires tenant version 66 or newer.

The tier ({{ t("--performance-tier")? }}) sets how many cores the run uses: 48 on standard (the default), 96 on fast and 192 on turbo. The budget buys its compute hours divided by the cores in wall-clock time, so a faster tier spends the same budget in less time. For example, 24 compute hours on standard (48 cores) is half an hour.

Setup comes out of the same budget, so the run fuzzes only for the time that setup leaves. For example, 12 compute hours on standard is 15 minutes, and a setup that takes 5 minutes leaves about 10 minutes of fuzzing. A faster setup buys more fuzzing from the same budget.

The minimum budget is a quarter of the tier's cores: 12 compute hours on standard, 24 on fast and 48 on turbo.

{{ t("--setup-timeout")? }} sets how long setup can take before the run fails immediately. Use it to fail fast, and to debug a setup that takes too long. The default is 5 minutes, and the range is 1 to 30 minutes. Requires tenant version 66 or newer.
  {{ t("snouty launch --launcher basic_test --config ./config --setup-timeout 10m")? }}
{% else %}
{{ t("--duration")? }} sets how long the run fuzzes, after setup.

The tier ({{ t("--performance-tier")? }}) sets how many cores the run uses: 48 on standard (the default), 96 on fast and 192 on turbo.
{% endif %}

Extra parameters can be passed with --param:
  snouty launch --launcher basic_test --config ./config \
    --param antithesis.integrations.github.token=TOKEN \
    --param my.custom.property=value

User-defined attributes are params with an `attrs.` prefix. The server records them on the run and `snouty runs show` lists them:
  snouty launch --launcher basic_test --config ./config \
    --param attrs.team=payments \
    --param attrs.branch=main \
    --param attrs.build=12345

The launch records the commit, branch and repository of the git checkout that holds the config dir (or the current directory, without --config). In GitHub Actions, it also records the pull request and the user who started the workflow. `snouty runs show` lists them under Version Control. A {{ t("--param")? }} replaces a recorded value, and {{ t("--no-vcs")? }} records no commit, branch, repository or pull request.

In GitHub Actions, set ANTITHESIS_GITHUB_TOKEN to a GitHub token that can write commit statuses, and the run shows as the `continuous-testing/antithesis` commit status of the commit: pending at launch, and the result when the run ends. With {{ t("--test-name")? }}, the status is `continuous-testing/antithesis (<test-name>)`.

Additional container images that the config parser can't discover (e.g. an image referenced only in a Kubernetes CRD field) can be registered with the antithesis.images param, a semicolon-delimited [REGISTRY/]NAME(:TAG|@DIGEST) list:
  snouty launch --launcher basic_k8s_test --config ./config \
    --param 'antithesis.images=app@sha256:...;db:latest'

Add --json for machine-readable output. The launch response prints as one JSON object:
  snouty launch --json --launcher basic_test --config ./config |
    jq -r .runId

Next, wait for the run to finish with `snouty runs wait <run_id>`. The run ID is the `run_id` value in the launch output, or `.runId` in the --json output. To watch it live, use `snouty runs stream <run_id>`.

Credentials come from `snouty login` or from the environment variables below. Tenant and repository may be set via the environment variables below, or in a settings file (./.snouty.toml by default; see the global --settings/--profile flags and the README). Environment variables take precedence.

Environment variables (override any settings file):
  ANTITHESIS_TENANT       Your Antithesis tenant name.
  ANTITHESIS_API_KEY      API key authentication.
  ANTITHESIS_USERNAME     Username (deprecated).
  ANTITHESIS_PASSWORD     Password (deprecated).
  ANTITHESIS_REPOSITORY   Container registry for pushing images.
  ANTITHESIS_GITHUB_TOKEN GitHub token used by Antithesis to update GitHub commit status.
  SNOUTY_CONTAINER_ENGINE Force "docker" or "podman" (auto-detected by default).
