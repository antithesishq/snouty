# Opt-in features
#
# A feature gates a command that isn't ready to be on for everyone — because
# the Antithesis API it calls is still changing shape, or because most tenants
# can't serve it yet. Gating lets such a command ship in a release without
# putting it in front of users who would only hit a wall.
#
# Features are enabled by id in SNOUTY_UNSTABLE_FEATURES, a comma-separated list. They
# are deliberately an environment variable and not a setting: the gate decides
# which subcommands the parser has, so it must be known before the command
# line is parsed, and a setting can't be read that early without first parsing
# --settings/--profile — which would mean parsing the command line twice.
#
# No command is gated now. `runs-exec` gated `snouty runs exec` until the
# command became stable, and its id is retired.

# 1. `runs exec` is in `runs --help`, and is callable, with no feature set.
#    (It gets as far as needing credentials, which is proof no gate stopped
#    it.)
snouty runs --help
stdout 'exec.*Execute a command in a run'
! snouty runs exec run-1 -123 1.0 'uname -a'
stderr 'No Antithesis credentials found.*'

# 2. Unknown ids are carried rather than rejected: one exported
#    SNOUTY_UNSTABLE_FEATURES is shared by every snouty on the machine, so an id
#    from a newer build, or a retired one, must not break this one.
env SNOUTY_UNSTABLE_FEATURES=from-the-future,runs-exec
! snouty runs exec run-1 -123 1.0 'uname -a'
stderr 'No Antithesis credentials found.*'

# 3. `snouty doctor` reports the enabled features, so what is on is visible
#    alongside the rest of the resolved configuration. An id this build does
#    not know is echoed, not dropped. doctor exits non-zero here (no
#    credentials or container runtime), but the table still prints.
! snouty doctor
stderr 'features.*from-the-future, runs-exec'

# 4. Whitespace and empty entries are ignored. (`set-env` keeps the spaces;
#    the `env` directive would split on them.)
set-env SNOUTY_UNSTABLE_FEATURES  a , ,b
! snouty doctor
stderr 'features +a, b$'

# 5. The row is omitted entirely when nothing is set — an empty row would be
#    noise on every ordinary run. An empty value is "unset", not "a feature
#    named the empty string".
env SNOUTY_UNSTABLE_FEATURES=
! snouty doctor
! stderr 'features.*'

# 6. A settings file cannot enable a feature — the key is not a setting, so
#    it is ignored like any other unknown key rather than erroring.
! snouty --settings features.toml doctor
! stderr 'features.*'

-- features.toml --
features = ["from-the-future"]
tenant = "from-file"
