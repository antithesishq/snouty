Show which instrumented code of a run it reached, as a tree of modules, files, classes and functions. Use it to find code that the run never reached, and the moment where it first reached a location. Runs created before release 67.6 have no coverage.

`runs coverage` is an unstable feature: its flags and output can change in any release. Enable it with `SNOUTY_UNSTABLE_FEATURES=coverage`.

Each line starts with the share of the locations under it that the run reached, and the reached and total counts: `66.7%  2/3`.

{{ t("--rollup")? }} sets the deepest level: `file` (the default), `function`, or `none` for every location. With `none`, a table of the function's locations hangs under each function, in source order: LOCATION, the line and column where it starts, then INPUT_HASH and VTIME, the moment where the run first reached it. A reached location is plain, an unreached one dim, and an empty cell is `-`. Several locations can start at one place, such as the copies of a generic function, or the two outcomes of a branch. Identical rows print once, followed by `×N`, the number of locations. A row of empty cells comes last.

Use {{ t("--module")? }} to show only a module, by the ID that `{{ t("runs modules")? }}` lists.{% if cli %} Give it more than once for more modules.{% else %} List more IDs for more modules.{% endif %}{% if cli %} To narrow further, such as to a file, class or function, filter the {{ t("--json")? }} output, for example with `jq`.{% endif %}

{% if cli %}
VTIME is cut to five decimals, which still names a moment at or before the first reach. With {{ t("--detail")? }}, it prints whole. On a terminal, file names are shortened at the start, and other names at the end. After the output, a status line on stderr counts the locations, and gives the share reached and the run's status.
{% else %}
VTIME prints whole. A status line under the output counts the locations, and gives the share reached and the run's status.
{% endif %}

With {{ t("--json")? }}, each module prints as one JSON object on its own line, nested like the text down to {{ t("--rollup")? }}: the module's `module_id`, `module_name`, `language`, `reached` and `total`, then `files`, each with its `classes`, each with its `functions`. A class is its full name, or null for free functions. A function has the `first_reached` moment of its earliest location, and with `none` its `locations`, as the API sends them, with each vtime as a JSON number. The counts are exact.

While the run is in progress, the output is the coverage up to now. The run must be ready or complete. If it is not, the command waits until it is ready, and says that it waits.

Examples:
  {{ t("snouty runs coverage <run_id>")? }}
  {{ t("snouty runs coverage <run_id> --rollup function --module <module_id>")? }}
  {{ t("snouty runs coverage <run_id> --rollup none --module <module_id>")? }}
