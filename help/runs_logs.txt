Stream the logs of one timeline of a run.

How a run is structured: An Antithesis run is a tree of timelines, not one history. A timeline is a series of input_hashes. An input_hash is a hash of every input Antithesis sent up to that point. Antithesis branches a timeline by sending an input from some moment, which creates a new input_hash. Every event has an input_hash and a vtime, and one input_hash can have zero or more events. Events that share an input_hash are on the same timeline. vtime is the virtual time at which the event was emitted on its timeline. Antithesis virtualizes the clock, so vtime can jump forward by any amount, but it never goes backward. vtime orders events only within one timeline.

{{ t("input_hash")? }} identifies the timeline: the hash of every input Antithesis sent from the root to that point. Logs stream from the root (or {{ t("--begin-vtime")? }}) to the timeline's current end; a run in progress can extend the timeline, so the same {{ t("input_hash")? }} can return more logs later. Give {{ t("vtime")? }} to end the stream at that moment instead.

Each event has its moment (an input_hash and a vtime), its source, and its payload: log output, an SDK assertion, a fault, a container lifecycle change, or a test composer command.

With --detail, VTIME and the source print whole, and indented lines under an event give its source location, as `@ file:function:line`, and the details that it carries, such as an SDK assertion's details, as `details {...}`.
