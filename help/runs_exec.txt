Execute a bash script in a run that is in progress, at a moment.

The run must be ready. It can be a test run or a debugging session. The exec command will wait until the run is ready before running the script.

The script executes on a fresh branch of the multiverse, so it does not interact with other work happening in the session, like fuzzing or other executing commands.

{{ t("input_hash")? }} and {{ t("vtime")? }} identify the moment to execute at, and the moment must be warm. A warm moment is a moment that is loaded into the run. Every moment generated in the run is warm: by fuzzing, and by an earlier `{{ t("runs exec")? }}`, so the end moment of one command is warm for the next. A moment from another run is cold, and the server must rewarm it: load it by replaying the inputs of the run it comes from. A debugging session rewarms a moment of the run it was launched from without a source. For a moment of any other run, name that run with {{ t("--source-run-id")? }}. Rewarming a moment can take minutes and depends on the magnitude of the vtime. {% if cli %}The `--timeout` flag{% else %}`timeout`{% endif %} does not apply to the time it takes to rewarm a moment. Find a moment with `{{ t("runs properties --detail")? }}`{% if cli %}, `{{ t("runs search")? }}`, or `runs events`{% else %} or `{{ t("runs search")? }}`{% endif %}.

The script executes on the host, or in the container that {{ t("--container")? }} names. The command needs tenant release 64.0 or newer; `{{ t("snouty doctor")? }}` reports the tenant release.

{% if cli %}Without --events, the script's stdout and stderr stream to snouty's stdout and stderr. With --events, snouty prints every event of the timeline to stdout while the script executes, as `snouty runs logs` prints them: the script's output, the workload's logs and assertions, and Antithesis events. On exit, a trailer on stderr documents the branch's end moment, to chain a follow-up command from.{% else %}Without `events`, the result's first content block is the script's output. With `events`, it is every event of the timeline while the script executes, as `runs_logs` returns them: the script's output, the workload's logs and assertions, and Antithesis events. A second block holds the script's error output, why the command failed when it fails, and, when the script exits, a last line `end moment: HASH VTIME`: the moment to chain a follow-up call from. The two blocks do not keep the order of the output and the error output; set `json` to get one stream in order.{% endif %} The command fails when the script fails, times out, or its stream ends early.

To run more at the moment that a script left, pass its end moment as the next call's input_hash and vtime:
  {{ t("snouty runs exec <run_id> <end_hash> <end_vtime> 'cat /tmp/state'")? }}

{% if cli %}
Omit SCRIPT to read the script from stdin — a pipe, a redirect, or a heredoc.
{% endif %}

Examples:
  {{ t("snouty runs exec <run_id> <hash> <vtime> 'uname -a'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --container <name> 'ps aux'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --events 'sleep 5'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --source-run-id <other_run_id> --timeout 5m 'ls'")? }}
{%- if cli %}
  {{ t("echo 'ps aux' | snouty runs exec <run_id> <hash> <vtime>")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> < script.sh")? }}
{%- endif %}

{% if cli %}
Add --json for machine-readable output. Each frame of the stream prints as one JSON object on its own line, and the trailer is left out:
  {% filter cmd %}
  snouty --json runs exec <run_id> <hash> <vtime> 'ls' \
    | jq -r 'select(.output_text != null).output_text'
  {% endfilter %}
{% else %}
With {{ t("--json")? }}, each frame of the stream prints as one JSON object on its own line. The last line is the exit result, and its `end_moment` is the moment to chain a follow-up call from.
{% endif %}
