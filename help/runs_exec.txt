Execute a bash script in a run that is in progress, at a moment.

The run must be ready. It can be a test run or a debugging session. The exec command will wait until the run is ready before running the script.

The script executes on a fresh branch of the multiverse, so it does not interact with other work happening in the session, like fuzzing or other executing commands.

{{ t("input_hash")? }} and {{ t("vtime")? }} identify the moment to execute at, and the moment must be warm. A warm moment is a moment that is loaded into the run. Every moment generated in the run is warm: by fuzzing, and by an earlier `{{ t("runs exec")? }}`, so the end moment of one command is warm for the next. A moment from another run is cold, and must be rewarmed before the script executes. Use {{ t("--source-run-id")? }} to load a moment from a different run. A debugging session needs no {{ t("--source-run-id")? }} for a moment of the run it was launched from. Rewarming a moment can take minutes, and takes longer for a larger vtime. {{ t("--timeout")? }} does not apply to the time it takes to rewarm a moment. Find a moment with `{{ t("runs properties --detail")? }}`, `{{ t("runs search")? }}`, or `{{ t("runs events")? }}`.

The script executes on the host, or in the container that {{ t("--container")? }} names. The command needs tenant release 64.0 or newer; `{{ t("snouty doctor")? }}` reports the tenant release.

{% if cli %}
Without --events, the script's stdout and stderr stream to snouty's stdout and stderr. With --events, snouty prints every event of the timeline to stdout while the script executes, as `snouty runs logs` prints them: the script's output, the workload's logs and assertions, and Antithesis events. Add --detail to print the events as `snouty runs logs --detail` does.

On exit, a trailer on stderr documents the branch's end moment, to chain a follow-up command from.
{% else %}
Without `events`, the result's first content block is the script's output. With `events`, it is every event of the timeline while the script executes, as `runs_logs` returns them: the script's output, the workload's logs and assertions, and Antithesis events.

A second block holds the script's error output, why the command failed when it fails, and, when the script exits, a last line `end moment: HASH VTIME`: the moment to chain a follow-up call from. The two blocks do not keep the order of the output and the error output; set `json` to get one stream in order.
{% endif %}

{{ t("--include-filtered-logs")? }} adds the logs that the run's log filters drop to the events: the lines that `antithesis.filter_logs_matching` and `antithesis.filter_source_matching` suppress (retroactive logging). It needs {{ t("--events")? }}. It adds a short setup step before the script executes, which {{ t("--timeout")? }} does not cover.

The command fails when the script fails, times out, or its stream ends early.

To run more at the moment that a script left, pass its end moment as {{ t("input_hash")? }} and {{ t("vtime")? }}:
  {{ t("snouty runs exec <run_id> <end_hash> <end_vtime> 'cat /tmp/state'")? }}

{% if cli %}
Omit SCRIPT to read the script from stdin — a pipe, a redirect, or a heredoc.
{% endif %}

Examples:
  {{ t("snouty runs exec <run_id> <hash> <vtime> 'uname -a'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --container <name> 'ps aux'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --events 'sleep 5'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --events --include-filtered-logs 'sleep 5'")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> --source-run-id <other_run_id> --timeout 5m 'ls'")? }}
{%- if cli %}
  {{ t("echo 'ps aux' | snouty runs exec <run_id> <hash> <vtime>")? }}
  {{ t("snouty runs exec <run_id> <hash> <vtime> < script.sh")? }}
{%- endif %}

With {{ t("--json")? }}, each frame of the stream prints as one JSON object on its own line. When the script exits, the last line is the exit result, and its `end_moment` is the moment to chain a follow-up call from.
